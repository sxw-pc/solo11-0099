# 工地巡检证据台

面向本地合成巡检数据的覆盖性核验。照片字节的 SHA-256、声明、轨迹和检查项进入 SQLite；决策引用证据，缺轨迹时不虚构位置。

`python -m sitewalk demo` 初始化、生成 fixture、导入、核验并打印 JSON 报告路径。`python -m sitewalk --help` 查看命令；`python -m pytest -q` 运行测试。Python 3.11+ 标准库运行，pytest 仅用于测试。

数据流：Plan → Point；Source → Photo / Track；Point → Item / Problem / Decision。位置用相邻轨迹点线性插值，轨迹缺口超过 10 分钟视为未知；核验规划有效期、点位半径、停留时长、检查项证据、跨点位或跨日期复用照片。问题状态为 found → assigned → rechecked → closed，非法状态转移报错。报告含坐标、照片哈希和未覆盖点位。

定位距离使用局部平面近似，适用于小型工区。室内楼层和多终端冲突属于未来边界，不在首版实现。

安装检查：在仓库目录运行 `python -m pip install . --no-build-isolation`；本地开发也可直接运行模块命令。报告同时生成 JSON 和 Markdown，`inspect` 子命令可追踪单个对象。

审计台账：Run 由规则版本和来源摘要确定，Evidence 关联原始对象与来源，Decision 引用 Run；重复核验保持同一输入的报告稳定。

原始来源字节保存在 SQLite BLOB 中，JSON 证据包以 Base64 表示字节；修改输入文件不会覆盖已采录证据。

## 材料过磅结算采录

`weigh-register` 把地磅合同的原始读数字节、相机车牌、拖挂 RFID、时刻、单价冻结为 `weigh_case`，只做点位与容量校验，不配对、不计价。`weigh-settle` 在离线范围（至多 12 毛重 / 12 皮重）内对每种预先约定的身份依据分别完整推演：

- 匹配引擎用记忆化 DFS 穷尽全部 (毛重, 可用皮重) 组合并记录状态数与并列数，先最大化合法完整票数，再按身份可信度、合同时差、配对 ID 字典序稳定裁定；同时保存"最近时刻优先贪心"结果作为反例对照（`fixtures/matching-trap.json`：贪心只结 1 票，全局匹配结 2 票）。
- 单票须同时满足合同时间窗、同身份依据链（相机与 RFID 不混用）、磅秤校准版本有效、进出工地记录一致、唯一纸票、正净重；皮重不可被两车共享。
- `camera_plate` 与 `rfid_trailer` 两条身份链都完整落库，总净重相同但逐车/收货方付款可不同；只确认合同事先签约的一条，另一条为 `comparison` 比较证据，禁止签收。
- 票据绑定原始读数字节哈希、校准版本、匹配链与司机/收货签收。打印作业幂等：纸票在司机手上时禁止再出；中心 ACK 丢失须经现场扫描登记 `lost` 后才能凭重印链补票，不产生第二张同时有效票；未知纸票进入待核实争议，重复回执被拒。
- 更正（皮重、拖挂交换、校准）不重写已签收净重：原票留档为 `superseded`，新票重新签收，并逐票生成替代关系与差额单。

`weigh-report` 输出逐票 JSON 与 Markdown 地磅单（含毛重/皮重来源、读数哈希、净重、付款、推演证明、争议单与差额单），不是只给净重总和。原巡检覆盖与土方量流程不受影响。
